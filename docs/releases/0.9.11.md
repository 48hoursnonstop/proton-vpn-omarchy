# 0.9.11 — Split-tunneling fixes and bounded Stealth recovery

This release fixes packet-mark handling and Qt 6.12 compatibility, improves
runtime recovery and adds temporary foreground API recovery through Stealth.

- IPv6 destination keys no longer overwrite the eBPF UID. Each UDP destination
  recomputes its socket mark from the current application policy, clearing stale
  IP/LAN/DNS bypass decisions while preserving foreign marks.
- The agent observes owned tunnels with the panel closed and retries unexpected
  drops using bounded recovery. Manual cancellation, logout and external VPNs
  do not start that recovery.
- Local logout completes before a bounded best-effort remote revocation.
  Account plans and replaceable client configuration refresh periodically;
  **Account → Refresh account** requests an immediate update. Physical location
  is invalidated on network changes and never refreshed through a VPN exit.
- Foreground API transport failures may use temporary Stealth Guest Hole recovery
  when Alternative Routing is enabled. Recovery has cancellation and exact-profile
  cleanup. It preserves existing VPNs and active blocking kill switches.
- QML explicitly resolves `Commons.Color` on Qt 6.12. Keyboard fixtures avoid
  timer reentry during QtTest event injection. The Arch package hook recognizes
  both official ProTun service executable paths.

## Validation and limits

172 Rust tests pass; nine opt-in tests are skipped in the normal suite. Four
corrected eBPF programs pass the kernel verifier without attachment. Isolated
IPv4/IPv6 routing and kill-switch checks, 14 QML fixtures, the closed native host,
installer fixtures and libnm DNS normalization checks pass.

Authenticated Stealth connections and HTTPS succeeded on MX#191, NL#877 and
CH#1110 on the test network. A repeated MX test verified a changed public exit
with two independent HTTPS services and routing through the VPN interface.
No test-account IP, credentials or account identifiers are published.

Guest Hole uses full-tunnel routes and tunnel DNS temporarily, which can briefly
interrupt other IPv4 traffic. ProTun v1 supports direct endpoints, not relay-only
entries requiring the newer engine contract. A complete Guest Hole API recovery,
real-drop reconnection and the full UDP/IPv6/split/kill-switch traffic matrix
remain unverified. Success on these three servers does not establish support
for every server or network policy.

Automatic crash reports remain disabled by community-project scope. Languages
remain English and Spanish. Secret Service namespaces, RC1 session envelopes,
profile schema and JSON Lines v1 remain compatible.

## Update

```bash
omarchy plugin update proton.omarchy
~/.config/omarchy/plugins/proton.omarchy/scripts/install-backend --install
```

The guided installer verifies the exact package size and SHA-256, detached
release signature and GitHub/Sigstore build provenance before installation.
