# 0.9.7-rc1 — Recover saved sessions after login

When the agent starts before GNOME Keyring is available or unlocked, earlier
versions can report a signed-out account even though the saved credentials
are still present. This candidate keeps the account pending, restores the
session once storage is accessible, and then allows startup auto-connect.

## Changes

- Retry saved-session restoration with exponential backoff from one second
  to a maximum interval of 30 seconds. No open plugin window is required.
- Show **Waiting for keyring** with **Retry session recovery**, in English
  and Spanish, instead of asking for credentials while storage is unavailable.
- Permit silent passwordless-keyring unlocking without repeatedly opening
  password dialogs for encrypted collections.
- Keep persisted VPN settings loaded while waiting for the keyring.
- Serialize restoration with authentication operations and block login/logout
  while the saved account is unresolved. Queued retries cannot resurrect a
  deliberately signed-out session.
- Handle restoration completing during the initial auto-connect request,
  so the signed-in transition cannot be missed.

The `Proton VPN for Omarchy` namespace and `pvom1:` / `pvom-index1:` envelopes
from 0.9.6-rc1 are unchanged. This candidate does not reset keyrings, change
their passwords, or remove shared Proton or unrelated credentials. An
encrypted keyring still needs to be unlocked through desktop authentication.

## Try the candidate

For an existing, unmodified plugin checkout installed through Omarchy:

```bash
git -C ~/.config/omarchy/plugins/proton.omarchy fetch origin tag v0.9.7-rc1
git -C ~/.config/omarchy/plugins/proton.omarchy switch --detach v0.9.7-rc1
```

Open the plugin and use its verified backend installer to update to core
`v0.9.7-rc1`, packaged as `0.9.7-1`. Update both components: the new waiting
view is in the plugin, while credential recovery runs in the backend.
Users without the plugin can first add the stable repository through
`omarchy plugin add`, then select the candidate as above.

To verify the affected scenario, reboot normally with auto-connect enabled.
If the keyring needs a password, unlock it through the desktop. The account
should return without another Proton login, and auto-connect should follow.
**Retry session recovery** requests an immediate check after unlocking.

If the problem persists, report the plugin version, `pacman -Q
proton-vpn-omarchy`, whether desktop autologin is enabled, and whether unlocking
the keyring followed by retry restores the session. Do not send credentials or
keyring files. Reinstallation is not required for this update.

## Validation

- 132 workspace tests pass, including persisted settings during failed reads,
  empty-keyring handling, restoration after failures, retry idempotence, and
  the auto-connect startup race.
- Isolated GNOME Keyring tests pass for passwordless GKeyFile and encrypted
  collections, including late daemon startup, encrypted unlock in place, and
  two daemon restarts per storage format. Shared and unrelated synthetic
  credentials survive. These tests also run in release CI.
- Read-only validation against an existing 0.9.6 private desktop session
  passes without changing stored session or index bytes.
- All ten UI fixtures pass, including recovery, keyboard retry, duplicate
  request prevention, English/Spanish copy, and returning to login or Home.
  Installer, traffic, and closed native Wayland-host checks also pass.

The release package is built from the signed core tag, attested by GitHub
Actions, and signed with the published release key. The plugin installer pins
the exact package, signature, provenance bundle, source commit, and tag.

This is a release candidate. The isolated tests reproduce the identified
failure conditions; affected-user reboot confirmation is still needed before
claiming that every reported keyring/session-loss issue is resolved.
