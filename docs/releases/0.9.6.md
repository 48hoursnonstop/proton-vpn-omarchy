# 0.9.6 — Native Omarchy interface and safe session storage

Stable release from `main`, bringing the candidate frontend and backend work
together. The frontend installs core `v0.9.6`, packaged as `0.9.6-2` so existing
`0.9.6-1` candidate installations receive the backend update.

## Interface and interaction

- Native Omarchy colors, typography and controls across Home, locations,
  profiles, connection details, settings, account and setup.
- A shared workspace preserves search, scroll position and navigation context.
  Keyboard activation, focus restoration and search cancellation follow the
  same paths as pointer interaction.
- Brief 120ms page, disclosure and feedback transitions. Pages are interactive
  immediately; rapid navigation does not queue animations. The inline plugin
  setting `reducedMotion: true` disables the added transitions; Omarchy owns
  the shell panel and toolkit control animations.
- Connection details and Home share one traffic history: one sample per second
  while connected and the agent is available, up to five minutes in RAM.
  Collection continues when changing pages or closing the panel, while the
  plugin remains loaded. Reloading the plugin clears this history. Gaps remain
  visible, and disconnects or connection/counter changes reset the series.

## Backend and keyring compatibility

- Preserve the RC1 `Proton VPN for Omarchy` Secret Service namespace and
  `pvom1:` / `pvom-index1:` ASCII-safe storage formats. Existing RC1 sessions
  remain readable without signing in again.
- Validate session and account-index payloads before writing. Token refreshes
  avoid rewriting unchanged account metadata.
- Record the no-reimport marker before sign-out removes a private session,
  so an interrupted cleanup cannot silently restore a shared legacy login.
- Keep shared Proton entries as a migration source only. Private credential
  operations leave shared Proton and unrelated application entries untouched.
- Reject oversized data, normalize duplicate account entries and keep
  credential debug details out of ambiguous-keyring error messages.

The Arch package is built and tested by the pinned GitHub Actions workflow
from the signed core tag. The installer checks the exact artifact sizes,
SHA-256 digests, GitHub/Sigstore build provenance and OpenPGP signature before
requesting installation. Frontend and backend remain independently packaged.

## Validation

- Backend: formatting, Clippy with warnings denied, 128 passing workspace
  tests, and ProTun metadata normalization/rollback checks.
- Passwordless GNOME Keyring: synthetic migration, restoration and sign-out
  across two actual daemon restarts in an isolated D-Bus session. Shared and
  unrelated synthetic credentials survived.
- With the account owner's explicit consent, an existing desktop session was
  read and round-tripped in memory using the stable encoder. Stored session
  and account-index bytes were checked unchanged; no secrets were printed.
- Frontend: UI, interaction, motion, continuous traffic history and installer
  runtime checks, plus native plugin manifest validation.
- The unmodified installer verified the public stable downloads, provenance,
  signature and package identity with `--verify-only` in a read-only filesystem
  sandbox. Its `/usr/bin/gh` path used the already installed GitHub CLI, with
  temporary verification/cache directories; no backend package was installed.
- Documentation renders use synthetic state in offscreen floating windows.
  The About capture reflects the stable version; the other captures retain
  the already validated RC4 interface.

The desktop credential check performs no login, token refresh or VPN change.
The release does not claim a fresh end-to-end VPN connection test or GPU
frame-time profiling. Traffic samples are not persisted by the frontend.
