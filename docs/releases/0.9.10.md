# 0.9.10 — Respect cancellation during startup and resume

The backend review reproduced two cancellation gaps and fixes both:

- Cancelling or disconnecting while the startup agent waits for the keyring
  remains effective after the saved account finishes restoring. Explicitly
  disabling and re-enabling auto-connect can start a new sequence.
- Resume reconnection stops after cancellation, manual connection/disconnection,
  logout or a permanent connection error. Transient connection failures still
  retry within the existing bounded schedule.

Security-key login cancellation does not suppress a later successful VPN
sign-in. No UI, theme, keyring namespace, credential envelope, profile schema or
IPC wire-format changes are included. Storage remains compatible with 0.9.6-rc1.

The new regressions failed against the previous implementation. All 158
workspace tests now pass; eight opt-in tests remain ignored. The signed release
build repeats the suite and isolated passwordless/encrypted GNOME Keyring tests.

Read-only checks after the machine's subsequent boot confirmed that 0.9.9 had
restored the saved account and retained all profiles and recents. Live VPN
connection tests were not attempted on the protected network.

## Update

Update the plugin and the matching **0.9.10-1** backend package:

```bash
omarchy plugin update proton.omarchy
~/.config/omarchy/plugins/proton.omarchy/scripts/install-backend --install
```

Opening the updated plugin also offers the backend update. The installer verifies
the exact package sizes and SHA-256 digests, release signature and GitHub build
provenance before installation.
