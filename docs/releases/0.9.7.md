# 0.9.7 — Recover saved sessions after login

When the agent starts before GNOME Keyring is available or unlocked, earlier
versions can report a signed-out account even though saved credentials are
still present. Version 0.9.7 waits for storage, restores the session when it
becomes accessible, and then resumes startup auto-connect.

## Changes

- Retry saved-session restoration in the background, with delays from one
  second to a maximum interval of 30 seconds. The plugin can remain closed.
- Show **Waiting for keyring** and **Retry session recovery** in English and
  Spanish while credentials are inaccessible.
- Allow silent unlocking of passwordless keyrings without repeatedly opening
  password dialogs for encrypted collections.
- Keep saved VPN settings loaded during recovery and serialize recovery with
  authentication operations to avoid conflicting login or logout requests.
- Handle recovery completing during the initial auto-connect request.

The private `Proton VPN for Omarchy` namespace and the `pvom1:` /
`pvom-index1:` credential formats from 0.9.6-rc1 are preserved. No keyring reset,
password change, or shared-credential cleanup is needed. An encrypted keyring
still needs to be unlocked through desktop authentication.

This stable release contains the recovery behavior tested in 0.9.7-rc1. The
backend package is **0.9.7-2**, so both 0.9.6 users and RC users can upgrade.

## Install or update

For a new installation:

```bash
omarchy plugin add https://github.com/48hoursnonstop/proton-vpn-omarchy.git --enable
```

For an existing plugin on `main`:

```bash
omarchy plugin update proton.omarchy
```

If you explicitly checked out the RC tag, return to `main` first:

```bash
git -C ~/.config/omarchy/plugins/proton.omarchy switch main
omarchy plugin update proton.omarchy
```

Then open the plugin and use **Install backend** / **Update backend**, or run:

```bash
~/.config/omarchy/plugins/proton.omarchy/scripts/install-backend --install
```

The installer verifies the pinned package size, SHA-256, release signature,
and GitHub build provenance before installation, then configures and restarts
the agent. Update both the plugin and backend; reinstalling is unnecessary.
If the shell still displays the previous UI, run `omarchy restart shell`.

## Validation

- 132 workspace tests pass, covering recovery, persisted settings, retry
  idempotence, and the auto-connect startup race.
- Isolated GNOME Keyring tests cover passwordless and encrypted storage,
  delayed daemon startup, encrypted unlock in place, and two daemon restarts
  per format. Shared Proton and unrelated synthetic credentials survive.
  These checks also run in release CI.
- Read-only validation against an existing 0.9.6 private desktop session
  passes without changing stored session or index bytes.
- All ten UI fixtures pass, including keyboard recovery, English/Spanish
  copy, and transitions to login or Home. Installer, traffic, and closed
  native Wayland-host checks also pass.

The tests reproduce the identified startup failure. They do not establish
that every reported session-loss problem has the same cause. If a normal
reboot still asks for a Proton login, report both component versions, whether
desktop autologin is enabled, and whether unlocking the keyring followed by
**Retry session recovery** restores the account. Do not send credentials or
keyring files.
