# 0.9.9 — Reliable startup and cancellable connections

This release brings the reviewed startup and LAN fixes together with the
connection and Windows 5.1.8 parity improvements previously tested in the
local preview. Update both the plugin and the **0.9.9-1** backend package.

## Changes

- Keep Proton's in-tunnel gateway out of LAN bypass routes so Allow LAN does
  not send the Local Agent control connection onto the physical network.
- Retry transient startup failures in the agent, including on Ethernet and
  while the panel is closed. Eight attempts use bounded backoff; cancellation,
  manual connection/disconnection and disabling auto-connect stop retries.
- Wait for persisted startup preferences before activating the backend. A
  later keyring restoration cannot undo a cancelled connection attempt.
- Keep **Cancel** available during connection preparation and tunnel startup,
  reject duplicate cancellation requests, and wait for ProTun readiness
  instead of aborting on the first Local Agent socket timeout.
- Verify signed server endpoints before creating VPN profiles. Upgrade old
  unsigned catalogs and show Smart Routing physical-host locations separately
  from the VPN exit country and Secure Core entry country.
- Validate Proton TLS pins before sending credentials and use the fixed
  official account API as a fallback, retaining certificate verification.
- Normalize city/state grouping consistently and dismiss connection feedback
  after its configured visible interval, without recording a vote or enabling
  usage statistics. Existing Omarchy styling and reduced motion are preserved.

The private keyring namespace, `pvom1:` and `pvom-index1:` formats remain
compatible with 0.9.6-rc1. The updater does not reset the keyring or require a
fresh sign-in merely because the package changed.

## Update

For an existing installation tracking `main`:

```bash
omarchy plugin update proton.omarchy
~/.config/omarchy/plugins/proton.omarchy/scripts/install-backend --install
```

Opening the plugin also offers the matching backend update. The installer
checks exact sizes, SHA-256, the release signature and GitHub build provenance
before installation. If the shell still displays the old UI, run
`omarchy restart shell`.

Users of a local preview must preserve their local changes before returning
the plugin to `main` and remove their preview service override to use the
packaged backend. A normal installation does not have that override.

## Validation

- 153 workspace tests pass with the locked dependencies.
- All 13 UI fixtures, the installer fixture and the closed native Wayland
  host pass. Startup, cancellation, Smart Routing, feedback and keyring
  recovery use synthetic data and floating offscreen windows.
- The production signed-catalog fixture verifies all 18,879 active physical
  endpoints in the cached official catalog without sending credentials or
  creating a tunnel.
- Isolated passwordless/encrypted keyring recovery and daemon restarts pass,
  as do the disposable IPv4/IPv6 marked-route and kill-switch checks.
- Release CI repeats the workspace tests and isolated GNOME Keyring checks.

No live VPN connection or reboot was tested during this release preparation
because the current network is restricted.
