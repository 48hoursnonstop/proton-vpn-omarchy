# 0.9.6-rc2 — Native panel redesign

This is a local frontend release candidate on `release/v0.9.6-rc2`.
It has not been installed over the active plugin or published to GitHub.
The installer still verifies and installs the signed backend `v0.9.6-rc1`.

Home now presents the connection state and an explicit Connect/Disconnect
button, followed by live traffic, connection details and up to three recent
connections. The full recent list remains available through View all.
Settings separates Connection from Application and groups advanced network
options behind an inline disclosure.

The panel and documentation renderer now share `ProtonWorkspace.qml`.
Omarchy continues to own popup placement, palette, font, spacing, borders,
corner radius and control state styling. Existing Proton assets and their
attribution remain intact. There is no additional UI framework or plugin skin.

## Keyboard and adaptation

- Tab / Shift+Tab traverse controls; focused content scrolls into view.
- Left / Right on navigation tabs, or Ctrl+Tab / Ctrl+Shift+Tab, change destinations.
- Ctrl+F opens and focuses location search.
- Up / Down inside lists reach rows beyond the currently instantiated delegates.
- Escape returns from a subpage, then closes the panel; Alt+Left goes back.
- Space / Enter activate rows, toggles and buttons. In-flight operations retain
  the existing guards against duplicate requests.

Navigation stays visible on secondary pages. It scrolls horizontally when the
labels exceed the available width, with a visible themed scrollbar and automatic
reveal of the selected/focused tab. Forms retain their labels while typing;
buttons and row descriptions wrap. Custom connection-icon pulsing was removed.
Traffic uses tabular figures and a shorter chart with the existing bounded
history and sampling behavior.

## Keyring and backend compatibility

`AgentState.qml` differs from RC1 only in its advertised client version.
`BackendInstaller.qml`, `CleanUninstaller.qml`, `scripts/install-backend` and
`scripts/uninstall` are byte-for-byte unchanged. Their release pins, hashes,
signature checks and backend calls are preserved. No credential namespace,
serialization, token refresh or migration logic is introduced by this frontend.
The separate core checkout's existing keyring changes remain untouched.

All UI fixtures use synthetic state. UI testing did not read credentials, sign
in, connect/disconnect the VPN, submit reports or change the user's settings.
The native host smoke test instantiated a closed panel on Wayland. Every visible
render was offscreen, so no preview was tiled by Hyprland.

## Design review

Mode: full within the production workspace and shared controls. Qt Quick/QML,
Quickshell and the existing `qs.Commons` / `qs.Ui` system. Project conventions
were taken from README, the translation catalog README and asset notices;
there is no repository AGENTS.md or separate contributor design guide.

Applied sources: [make-interfaces-feel-better](https://github.com/jakubkrehel/make-interfaces-feel-better)
and [skills](https://github.com/jakubkrehel/skills), including better-interface,
better-accessibility, better-layout, better-writing, better-typography,
better-colors and better-ui. The installed Omarchy skill supplied desktop and
theme integration conventions. Web-specific CSS and motion libraries were not
introduced into QML.

## Validation

Passed on the local Omarchy/Quickshell installation:

```bash
scripts/check-ui-runtime
scripts/check-traffic-runtime
scripts/check-installer-runtime
scripts/capture-showcase
bash -n scripts/capture-showcase scripts/check-ui-runtime
git diff --check
```

The UI runtime suite covers locale switching, location search, pagination,
profile destinations, workspace keyboard interactions and the closed native
Wayland host. Traffic and installer regression suites also pass. Nineteen
production route-entry images were regenerated in `docs/screenshots`.

Additional runs rendered all 19 route entries at 320px in Spanish and at a
24px base font (200%). After the overflow refinement, enlarged Home was checked
again in three themes. Empty, connecting and retryable-error Home states and
the new-profile/icon editor were also rendered at 320px in Spanish. Examples:

```bash
PROTON_SHOWCASE_WIDTH=320 PROTON_SHOWCASE_LOCALE=es-MX scripts/capture-showcase /tmp/proton-narrow
PROTON_SHOWCASE_FONT_SIZE=24 PROTON_SHOWCASE_LOCALE=es-MX scripts/capture-showcase /tmp/proton-large
PROTON_SHOWCASE_ONLY=home-standard PROTON_SHOWCASE_SCENARIO=error PROTON_SHOWCASE_WIDTH=320 PROTON_SHOWCASE_LOCALE=es-MX scripts/capture-showcase /tmp/proton-error
PROTON_SHOWCASE_ONLY=profiles PROTON_SHOWCASE_SCENARIO=edit-profile PROTON_SHOWCASE_WIDTH=320 PROTON_SHOWCASE_LOCALE=es-MX scripts/capture-showcase /tmp/proton-editor
```

The secondary-text/popup contrast measured 8.60:1 in Vantablack, 6.80:1 in
Tokyo Night, 7.12:1 in Flexoki Light and 7.72:1 in Catppuccin. The role also
checks the native normal, hover, focus and selected fills against 4.5:1.
These measurements do not certify arbitrary custom palettes or translucent
surfaces over arbitrary wallpapers.

Not verified in this UI pass: a real authentication/2FA or VPN session,
Orca/AT-SPI announcements, every secondary editor state, desktop placement on
every monitor arrangement, and performance under a production server catalog.

Verdict: **Approve for local RC evaluation within the inspected scope**.
Publishing, installing the candidate and validating live account/tunnel behavior
are separate from the completed source implementation and synthetic UI checks.
